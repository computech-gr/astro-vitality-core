## Submission checklist — manual evidence required

1. Verify the selected 2026 Space Apps challenge, current rules, eligibility, deadline, required deliverables, licenses and attribution from the official organizer. Do not assume a specific challenge category is confirmed.
2. Confirm the public demo URL and public GitHub repository can be accessed by an unauthenticated evaluator, without revealing private mission data.
3. Record a short demo with synthetic evidence: mission-scoped workflows, Health Intelligence research-only search/filter, and a visible limitations disclosure. Never imply live astronaut medical telemetry.
4. Upload the final video, slides and other required assets; capture the final URLs and independently verify that they open.
5. Capture the final full Git commit SHA, P47 GitHub Actions run URL, run result and submission confirmation/receipt.
6. Retain open-gate disclosures for offline OCR on a physical device in airplane mode, two-account Crew Self isolation, and independent scientific review.
7. Check all NASA/resource citations, licenses and names. Do not claim NASA endorsement, NASA operational use, clinical validation or flight readiness.

## Suggested evaluator walkthrough

Open the public application, explain the research-prototype and synthetic-data scope, show mission identity and access boundaries, demonstrate Health Intelligence's 54 review-only proposals with search/filter, then show evidence provenance and the explicit limitations. If authentication or device evidence is unavailable, demonstrate only what is genuinely accessible; use the existing documented fallback runbook.
