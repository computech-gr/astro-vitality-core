- Subdirectories have their own AGENTS.md (e.g. src/domain/AGENTS.md); read it before changing files there.
- Unapproved database changes are staged in supabase/pending/ (never supabase/migrations/) and exercised only by the disposable harness with FV0143_INCLUDE_PENDING=1; this keeps production migrations owner-gated.
- Greek scientific handbooks in data/scientific stay byte-identical; English display text lives in sibling _.en_.json layers joined by ID via src/domain/scientific-localization (keeps source traceability).
- P36 synthetic Cloud submission goes only through the server function in src/lib/p36-cloud-submission.functions.ts calling a security-definer RPC as the signed-in user (never the service role), and stays off unless the server flag P36_CLOUD_SUBMISSION_ENABLED is "true"; this keeps identity checks in the database and live writes owner-gated.
- Public competition team facts live in a browser-safe content module consumed by the team leaf route; the existing global shell owns its only header and the Project Guide retains its Team anchor to avoid duplicated content and navigation.
- The Project Guide roadmap is rendered only from the browser-safe registry src/content/roadmap-phases.ts, with every linked doc/verifier checked by tests; this keeps phase history evidence-backed and maintained in one place.
- Responsive presentation changes for frozen Health Intelligence sources belong in its leaf route wrapper; preserve the sealed source fingerprints and scientific classification values.
- Unified medical intake stores observations only as versioned envelopes (mitochondria.unified-observation.v1) through src/domain/health-intelligence/observation-store.ts: per-measurement catalog classification, reviewer-accepted rows only route to domain read models, and storage stays encrypted, append-only and offline (no cloud writes).
- Intake review selection and save eligibility share a pure selection module so bulk controls cannot include rows rejected by the existing save prerequisites.
- Medical advisor acknowledgment remains session-only for offline unified observations; v3 persistence and AI generation require owner-approved pending SQL plus an independently reconstructed authoritative synthetic evidence adapter, and fail closed without either. Caller-authenticated RPCs own append-only revisions, SHA-256 validation and atomic quotas; browser digests never attest evidence. Real-data AI is disabled, structured statements are rejected rather than rewritten, and reviewer membership is not licensure or a legal signature.
- Synthetic fixture review is a separate server-scope-resolved path with compact sorted-key v2 canonical evidence; offline reports never feed its authority. The pending fixture registry and test receipts are disposable-only until owner activation approval, because invented receipts are not human or scientific validation.
- Synthetic Q&A uses caller-scoped RPCs and the existing OpenAI Responses contract behind independent default-off disposable or production-synthetic gates; the production alternative pending bundle binds exact mission/crew prerequisites, predefined questions, atomic quotas and database-denied persistence, while exact fact-template validation rejects claims and exports re-read authority.
- Isolated browser acceptance must stop before runtime execution without independent local real-auth/data services; the preflight is a blocking infrastructure gate, never a substitute for authenticated browser acceptance.
- The staging target guard is offline string validation only and must reject shared domains/port and require explicit loopback permission; real service attestation remains separate because hostname matching cannot prove isolation.
- Security CI scans development dependencies and unfixed findings alongside production dependencies; compatible targeted Bun updates preserve transitive major branches rather than force incompatible overrides.
- The medical release workflow runs all offline verifiers including private-evidence gates, excludes explicitly service-dependent checks, and reports each validation step even after failures; an exact-commit code check never attests staging acceptance or production authorization.
- Final release diagnostics preserve verifier failures and their complete output; deterministic release samples must match the existing sealed manifest without changing evidence statuses or hashes, because reproducibility is not owner acceptance.
- CI generates ignored deterministic release samples before checks/tests and validates their sealed bytes; exact-commit reporting paginates runs and selects the newest run before its attempt number so stale successful runs cannot hide newer failures.

- The standalone production synthetic SQL overrides inherited ACLs on every v3 table, owned sequence and function, exposes only the four caller-scoped synthetic RPCs, and pins trusted ownership/search paths; RLS alone cannot guard TRUNCATE.
- The split synthetic candidate keeps schema and non-destructive disable SQL in pending files; seeding requires separately approved single-statement transport whose acceptance is established without a production probe, never an application endpoint. Reconciliation pins only the independently attested committed snapshot definition; original approved schema bytes and committed migration history remain immutable, and all other exact dependencies fail closed.
- Production synthetic Q&A must reserve nonrefundable lifetime attempt/cost holds through caller-scoped pending guard RPCs, then consume a server-held nonce dispatch permit immediately before the existing provider call; unknown outcomes permanently block concurrency and retaining-disable preserves audit/holds so crashes and quota lease expiry cannot replenish authorization. Trusted SQL-only one-lifetime activation and signed-in operator disable are independent of default-off deployment flags; legacy draft generation is disposable-only to prevent alternate-path bypass.
- Production synthetic Q&A uses a version-matched default-off practical guard: caller-scoped atomic irreversible attempts/estimated-cost holds and SQL-serialized dispatch/disable precede the single existing provider fetch; actual billing and already-permitted/in-flight transmission are not guaranteed because the owner approved those synthetic-only residual limitations, while production schema/deployment/window approvals remain separate.
- Production synthetic token admission uses a bundled local tokenizer in a server-only helper and caller-scoped guard status uses the existing authenticated console flow; this avoids provider traffic during validation and keeps operational state inaccessible to unscoped callers.
- Permanent synthetic research uses an independently provisioned v2 policy with irreversible monthly holds, rolling quotas, serialized dispatch/pause and explicit unresolved-attempt recovery; schema application revokes legacy admission so feature flags cannot bypass either policy.
- Research administration ownership is a SQL-provisioned separate role table, never inferred from mission membership; provider reconciliation is server-only, project-attributed and privileged only after caller-scoped owner validation, keeping administrative keys and billing writes outside browser authority.
- Server code that injects `fetch` as a dependency must pass a wrapper and invoke it with the global receiver; workerd throws "Illegal invocation" (before transmission) when the bare global `fetch` is called as a method of another object, which Node-based tests cannot detect.
- Synthetic tab convenience storage accepts only exact server-authorized fixture fact lines, binds account/scope/hash, and reauthorizes on remount/refocus; arbitrary manual text, rationale, consent and acknowledgment stay memory-only to prevent unencrypted medical-data or approval persistence.
- Synthetic activation status exposes explicit policy mode and sanitized diagnostic categories only; unavailable reads never imply eligibility and operator revision metadata never attests deployed bytes.
- Scientific reference pickers keep selection in component memory only and never promote source statuses; owner review provenance remains separate from operational authorization.
- Medical Report PDF export captures existing print styles in an isolated browser clone, paginates at report-item boundaries and generates local A4 bytes; fresh caller scope checks before export and after rendering prevent revoked or switched scope downloads without medical-data uploads.
- Universal medical document import uses PDF text geometry, header-aware catalog-ID rows and a bounded catalog-bound exact-alias clinical recognizer; ambiguous results/units are held with page/line/file evidence, never converted or fabricated, and clinical report collection metadata never supplies observation dates because human confirmation is mandatory.
- P36 hybrid document extraction shares one pipeline for all four health domains: deterministic parsing first, then automatic server-side AI suggestions via /api/medical-document-extraction (default-deny flags P36_DOCUMENT_AI_ENABLED / P36_REAL_DOCUMENT_AI_ENABLED, provider/model allowlist, content-free audit). Provider output is re-validated against the domain catalog, merged by evidence keys without overwriting deterministic rows, and never auto-saved; collection dates are never promoted to observation times.
- Daily Health Companion (/mission/companion) state is component-memory only; its domain rules are in src/domain/companion/AGENTS.md.
- Tests and verifiers resolve repository files relative to their own location (never a fixed checkout path such as /dev-server), and every workflow pins the same setup-bun commit SHA and Bun version; GitHub runners check out elsewhere and a missing spawn cwd surfaces as a misleading "ENOENT posix_spawn 'bun'".
