# Daily Health Companion rules

- Environment, checklist and participation stay in component memory only; Crew Self evidence is read through the existing scientific-evidence adapter, so colors stay data-quality states and cadences defer to approved mission protocols.
- Optional reminders are foreground-only, user-chosen intervals held in component memory (reminder-engine.ts) with an in-page notice and a permission-gated browser Notification; no persistence, push or service-worker scheduling, so no delivery guarantee is implied.
- The synthetic trend demonstration is a hardcoded, opt-in, memory-only illustration kept outside the Crew Self evidence path, so it can never be mistaken for, mixed with or exported as crew data.
- Crew Self series come from the shared canonical projection (see root AGENTS.md); handbook formats show quality as unknown and the provenance list is stacked cards on phones, a table from sm upward.
- Crew Self trend time-window/source filters and the provenance table are local presentation over already-authorized evidence (filterTrendObservations): no conversion, aggregation, thresholds or extra fetches, and they reset whenever the crew scope changes.
- Crew Self evidence is owned by the generation-guarded controller in crew-revalidation.ts: private data is hidden synchronously when the tab is backgrounded and on return/auth change, then only fresh membership and evidence reads may restore it; late responses are dropped and non-sensitive state (checklist, environment, synthetic demo, reminders) is never reset. No real-time claim while continuously visible.
- Synthetic Crew Self intake goes only through the default-off server function in src/lib/p48-synthetic-intake.functions.ts calling the existing ingest_mission_event RPC as the signed-in user; payloads come only from synthetic-intake.ts (classification fixed in code, catalog metrics, deterministic ids) and require a dedicated-mission, crew-self-only eligibility check plus explicit irreversible confirmation, so no other path can seed records.
